# 🧩 Графический редактор сценариев (Node Editor)

**Сценарист (Node Editor)** — визуальная среда проектирования сценариев автоматизации для аккаунтов Telegram. Позволяет создавать комплексные многошаговые сценарии без написания кода, сохранять их в файлы `.sgn` и выполнять на выбранных пулах аккаунтов.

---

## 1. Структура файла сценария (`.sgn`)

Файл с расширением `.sgn` представляет собой JSON-документ, описывающий узлы (блоки) и их параметры:

```json
{
  "nodes": [
    {
      "id": "1bc21e54-41f4-4be4-b2bc-841a78048130",
      "type": "random_delay",
      "title": "Случайная пауза",
      "pos_x": 511.0,
      "pos_y": 167.0,
      "params": {
        "min_seconds": 5,
        "max_seconds": 15
      },
      "outputs": [
        "next"
      ]
    },
    {
      "id": "71160e44-b28a-4d42-a9f3-f26e099387e4",
      "type": "end",
      "title": "Конец",
      "pos_x": 800.0,
      "pos_y": 167.0,
      "params": {},
      "outputs": []
    }
  ]
}
```

### Основные поля узла:
- `id` — уникальный строковый UUID блока.
- `type` — системный тип ноды (соответствует ключу в `NODE_SPECS`).
- `title` — пользовательское или отображаемое название блока.
- `pos_x`, `pos_y` — координаты узла на бесконечном холсте сцены.
- `params` — словарь значений настроек для конкретного блока.
- `outputs` — список исходящих портов/связей к следующим блокам.

---

## 2. Категории и спецификации блоков (`node_specs.py`)

Блоки разделены по функциональным категориям:

| Категория | Блоки | Описание |
|---|---|---|
| **Управление потоком** | `start`, `end`, `random_delay`, `condition`, `loop` | Точки входа/выхода, паузы, ветвления и циклы. |
| **Каналы и чаты** | `join_chat`, `leave_chat`, `check_channel_subscription`, `view_posts` | Вступление по ссылке, выход, просмотр постов, проверка подписки. |
| **Боты** | `bot_start`, `bot_send_message`, `bot_click_inline`, `bot_click_reply_keyboard` | Взаимодействие с ботами, ввод команд, клики по инлайн/реплай кнопкам. |
| **Работа с данными** | `get_file_line`, `set_variable`, `ai_generate_text` | Построчная ротация данных из файлов, локальные переменные, генерация текста через AI. |
| **Профиль и безопасность**| `change_bio`, `change_username`, `set_avatar` | Прогрев и наполнение метаданных аккаунта. |

---

## 3. Ротация файлов и контекст переменных

В `NodeScenarioExecutor` реализован общий потокобезопасный механизм ротации строк из файлов (`FILE_LINES_CACHE`, `FILE_LINE_CURSORS`):
- При использовании блока `get_file_line` несколько аккаунтов берут строки по очереди без дубликатов.
- Переменные контекста:
  - `{me_name}` — имя текущего аккаунта в ферме.
  - `{me_workdir}` — абсолютный путь к рабочей папке аккаунта.
  - `{me_proxy}` — текущий используемый прокси.
  - `{last_bot_username}` — юзернейм последнего задействованного бота.
  - `{last_chat_id}` — ID последнего чата/канала.

## 4. Жизненный цикл выполнения графа

```
Выбор аккаунтов в UI 
       │
       ▼
Проверка незаполненных параметров (EmptyParamsFillDialog)
       │
       ▼
Проверка наличия локальных файлов (аватары, списки ссылок)
       │
       ▼
Формирование очереди задач с семафором concurrency_limit
       │
       ▼
Старт NodeScenarioExecutor для каждого аккаунта
       │
       ├── Инициализация сессии MTProto
       ├── Пошаговый обход графа (start -> ... -> end)
       ├── Запись действий в аналитику
       └── Безопасный cleanup сессии
```

При запуске на нескольких аккаунтах применяется **шахматный старт** (stagger delay) со случайными задержками между аккаунтами для снижения подозрительности со стороны антиспам-систем Telegram.
